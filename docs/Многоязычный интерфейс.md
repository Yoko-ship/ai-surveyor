# Многоязычный интерфейс: русский, узбекский, английский

Задача заказчика от 21.09.2026: система работает на трёх языках. Словарь готов, страницы к нему ещё
не подключены — подключение делает заказчик, потому что страницы правят параллельно две другие команды.
Здесь написано, куда именно вставить код и что вставить.

## Что уже сделано

| Файл | Что это |
|---|---|
| `app/i18n/ru.json`, `uz.json`, `en.json` | словарь интерфейса, 653 ключа перевода в каждом файле плюс служебный блок `_meta` (в файле видно 654 записи), наборы ключей одинаковые |
| `app/i18n.py` | загрузка словарей, функция перевода, выбор языка, тексты проверок движка, маршруты |
| `tests/test_i18n.py` | проверка словаря и маршрутов |
| одна строка в `app/main.py` | `("i18n", "i18n_router")` в списке модулей в конце файла — маршруты появятся после перезапуска сервера (`run.bat`); пока сервер работает со старым кодом, `GET /i18n/langs` отдаёт 404 |

Маршруты сервера:

* `GET /i18n/ru.json`, `/i18n/uz.json`, `/i18n/en.json` — весь словарь одним файлом, с заголовком
  `Cache-Control: public, max-age=300`. Неизвестный язык — 404 с текстом «Языка «de» нет. Есть: ru, uz, en.»
* `GET /i18n/langs` — список языков и имя cookie.

Узбекский — латиница. Термины страхования взяты из `docs/i18n_terms.json` (формулировки юриста со ссылкой
на норму). Ключи, где узбекский перевод рабочий и ещё ждёт юриста, перечислены прямо в словаре:
`uz.json` → `_meta.draft`.

## Как устроены ключи

Плоские ключи с точками, сгруппированы по разделам:

| Раздел | О чём |
|---|---|
| `common.*` | кнопки, единицы («сум», «%», «дней»), общие ошибки, названия языков и тем |
| `calc.*` | экран расчёта `/ui`: продукт, класс, объект, сумма, срок, франшиза, факторы, вилка ставки, премия, «из чего сложилась ставка», оценка стоимости, фото и документы |
| `disclosure.*` | блок «что сказать клиенту» по ст. 63 Закона о страховой деятельности |
| `tg.*` | мини-апп `/tg`: нижняя навигация, вход, формы, согласование, фото, документы, бот |
| `status.*` | вердикты, статусы согласования, статусы пользователя и разбора документов |
| `doc.*` | типы документов и названия извлекаемых полей (из `docs/i18n_terms.json`) |
| `check.*`, `rec.*` | тексты проверок и подсказок движка по коду правила |
| `term.*` | 52 страховых термина |

Служебный блок `_meta` в каждом файле в перевод не участвует: ключи, начинающиеся с `_`, надо пропускать.

## Куда вставлять — по страницам

Общий порядок на каждой странице один и тот же:

1. подключить скрипт словаря **после** `/theme.js` (переключатель языка встаёт рядом с переключателем темы);
2. разметить подписи атрибутом `data-i18n="ключ"` — текст внутри тега заменится;
   для подсказок в полях — `data-i18n-placeholder`, для `title` — `data-i18n-title`.

Русский текст в HTML можно оставить как есть: он виден, пока словарь грузится, и служит запасным
вариантом, если сервер не ответил.

### 1. Экран расчёта — `/ui`

Правку вносят **не** в `docs/agent_ui.html`: эта страница собирается из шаблона.
Править `docs/agent_ui.template.html`, затем пересобрать: `python tools/ui_build.py`.

* **Где подключить скрипт:** последняя строка файла — закрывающий `</script>` (строка 1578).
  Скрипт словаря добавляется **после** него, новой строкой в самом конце файла.
  На `/ui` тег `<script src="/theme.js">` подставляет сервер (`app/main.py`, функция `ui()`),
  поэтому в самой странице его нет — словарь подключается после всего остального кода страницы.
* **Где разметить подписи:** блок `<header>` со строки 215 (`<h1>Новый расчёт</h1>` → `data-i18n="calc.title"`,
  `<p>Выберите продукт…</p>` → `data-i18n="calc.subtitle"`). Остальные подписи экран рисует из JavaScript —
  там вместо русской строки надо звать `T("ключ")` (функция из примера ниже), например
  `T("calc.sum_insured")` вместо `"Страховая сумма"`.

### 2. Мини-апп Telegram — `app/tg.html`

* **Где подключить скрипт:** самый конец файла, после строки `boot();` и закрывающего `</script>`

## Готовый код

Сохранить как `app/i18n.js` и отдать отдельным маршрутом рядом с `/theme.js` в `app/main.py`:

```python
@app.get("/i18n.js")
def i18n_js():
    from fastapi.responses import Response
    return Response((ROOT / "app" / "i18n.js").read_text(encoding="utf-8"),
                    media_type="application/javascript")
```

Подключение на странице — одной строкой: `<script src="/i18n.js"></script>`.

```js
/* Язык интерфейса: ?lang= → cookie lang → язык Telegram → ru. Ставит тексты по data-i18n. */
(function () {
  const LANGS = ["ru", "uz", "en"], NAMES = {ru: "Русский", uz: "Oʻzbekcha", en: "English"};
  const norm = c => { c = String(c || "").toLowerCase().split(/[-_]/)[0]; return LANGS.includes(c) ? c : null; };
  const cookie = n => (document.cookie.match("(^|; )" + n + "=([^;]*)") || [])[2];
  const tg = window.Telegram && Telegram.WebApp && Telegram.WebApp.initDataUnsafe.user;
  const lang = norm(new URLSearchParams(location.search).get("lang")) || norm(cookie("lang"))
            || norm(tg && tg.language_code) || "ru";
  let D = {};
  window.T = (key, vars) => {                       // T("calc.premium_note", {days: 90})
    let s = D[key] != null ? D[key] : key;
    if (vars) for (const k in vars) s = s.split("{" + k + "}").join(vars[k]);
    return s;
  };
  window.I18N_LANG = lang;
  function paint(root) {
    (root || document).querySelectorAll("[data-i18n]").forEach(e => e.textContent = T(e.dataset.i18n));
    (root || document).querySelectorAll("[data-i18n-placeholder]").forEach(e => e.placeholder = T(e.dataset.i18nPlaceholder));
    (root || document).querySelectorAll("[data-i18n-title]").forEach(e => e.title = T(e.dataset.i18nTitle));
    document.documentElement.lang = lang;
  }
  window.i18nPaint = paint;                         // звать после каждой перерисовки из JS
  function switcher() {
    const b = document.createElement("button");
    b.className = "theme-toggle"; b.type = "button"; b.style.right = "165px";  // слева от переключателя темы
    b.textContent = NAMES[lang];
    b.onclick = () => { const n = LANGS[(LANGS.indexOf(lang) + 1) % 3];
      document.cookie = "lang=" + n + ";path=/;max-age=31536000;samesite=lax";
      location.search = new URLSearchParams({...Object.fromEntries(new URLSearchParams(location.search)), lang: n}); };
    document.body.appendChild(b);
  }
  fetch("/i18n/" + lang + ".json").then(r => r.json()).then(j => { D = j; paint(); })
    .catch(() => {}).finally(switcher);             // словарь не пришёл — остаётся русский текст страницы
})();
```

Что делает код:

* выбирает язык в том же порядке, что и сервер (`app/i18n.py`, функция `pick_lang`);
* забирает `/i18n/{lang}.json` одним запросом и раздаёт тексты по `data-i18n`;
* даёт функцию `T("ключ")` для подписей, которые страница рисует из JavaScript,
  и `i18nPaint(узел)` — позвать после перерисовки куска страницы;
* рисует переключатель языка тем же классом `.theme-toggle`, что и переключатель темы
  (`app/theme.js`), и ставит его левее; выбор запоминается в cookie `lang` на год;
* если сервер не ответил, на странице остаётся русский текст — экран не ломается.

## Что открыть в `app/guard.py`

Сейчас `/i18n/*` закрыт сессией, как и всё остальное. Для внутренних страниц это правильно.
Если словарь понадобится **до входа** — на странице `/login` или на экране заявки мини-аппа, —
в `app/guard.py` надо добавить одну строку:

```python
WHITE_PREFIX = ("/tg/webhook/", "/i18n/")     # словарь интерфейса нужен на экране логина
```

Если заказчик заодно сделает `/i18n.js` по примеру выше, этот адрес тоже нужен в белом списке —
в `WHITE_EXACT`, рядом с `"/theme.js"`:

```python
    "/theme.js", "/favicon.ico", "/i18n.js",     # статика страниц входа
```

Словарь не содержит данных клиентов — это подписи интерфейса, открывать его безопасно.
Сам `app/guard.py` не тронут: строки выше вставляет заказчик.

## Тексты проверок движка

Проверки и подсказки движка (`app/engine.py`) приходят с кодом правила в поле `"rule"`.
Перевод берётся по коду, а не по русскому тексту:

```python
from app import i18n

lang = i18n.pick_lang(query_lang, cookie, tg_language_code)
for c in result["checks"]:
    txt = i18n.check_text(c, lang)        # {"title": …, "detail": …}
```

`check_text` сам определяет нужный вариант: у части правил один код даёт разные сообщения
(страховая сумма выше / ниже / равна оценке), и вариант выбирается по статусу и заголовку из движка.
Если движок добавит новое правило, страница не сломается: вернётся код правила, а пропуск попадёт
в `i18n.misses()` — там видно, что ещё не переведено.

Подсказки «как удешевить» переводятся так же: `i18n.rec_text(tip, lang)`.

**Что переводом не покрыто и покрыто быть не может:** предписания страхователю
(`preventive_measures`), названия факторов и вариантов в цепочке расчёта, названия продуктов
и классов. Эти тексты лежат в базе (таблицы `measures`, `coefficients`, `products`, `classes`),
а не в коде. Чтобы они заговорили по-узбекски и по-английски, в схему базы нужно добавить колонки
вида `name_uz` / `name_en` — это отдельная задача разработчику, её делает не словарь.

Отличия от примера выше:

* `T(key, fallback, vars)` — вторым аргументом идёт русский текст из кода. Нет ключа в словаре —
  остаётся русская строка, а не имя ключа. По той же причине `paint()` не трогает элемент,
  которого нет в словаре: на странице остаётся её собственный русский текст.
* Словарь для русского языка не запрашивается совсем — страницы и так написаны по-русски.
* Первая загрузка другого языка идёт синхронным запросом (текст не мигает), дальше словарь
  берётся из `localStorage` и тихо обновляется в фоне.
* Переключатель — три кнопки RU / UZ / EN, а не одна по кругу; выбор пишется и в cookie `lang`,
  и в `localStorage`, страница перезагружается с `?lang=`, чтобы сервер выбрал тот же язык.

**Маршрут `/i18n.js` и белый список появятся после перезапуска сервера** (`run.bat`):
пока сервер работает со старым кодом, `/i18n.js` отдаёт 404 и страницы остаются русскими —
это и есть запасной вариант, ничего не ломается.

### Ключей не хватило

`home.*` — заголовок и восемь карточек главной, четыре плитки со счётчиками;
«Войти через Telegram», «Продолжить с Google», «Получить код», «Зарегистрироваться»,
«Служебный вход», «Свернуть меню»; в админке — заголовки разделов и таблиц.

а доступ теперь открывается сам — поэтому на экране оставлен русский текст.
