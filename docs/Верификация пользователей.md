# Как люди проходят проверку в системе

Для руководителя. Техническая реализация — `app/auth.py`, страница входа — `/login`.

## Кто и как получает доступ

1. **Заявка.** Сотрудник открывает `/login`, вкладка «Подать заявку»: ФИО, телефон, логин, пароль, филиал, роль.
   Для роли «агент» обязателен **ID агента из реестра** — по Положению № 3845 агент без включения в реестр
   страховщика работать не может, и система заявку без ID не принимает.
2. **Сверка.** Администратор видит список заявок, сверяет с реестром агентов компании (ФИО, филиал, ID)
   и нажимает «Подтвердить» или «Отклонить». Отклонённая заявка удаляется. Оба действия пишутся в журнал.
3. **Вход.** Логин и пароль. Если у пользователя привязан Telegram — второй шаг: код из шести цифр,
   действует 5 минут. Пока бот не подключён, второй шаг отключён.
4. **Сессия** живёт 12 часов и продлевается при работе; выход — кнопкой.

## Регистрация через Telegram-бота (основной путь с 20.09.2026)

Подробно — `docs/Регистрация и роли.md`. Коротко:

1. Человек пишет боту `/start`, читает текст согласия на обработку персональных данных (версия ПД-1 от
   20.09.2026) и нажимает «Согласен на обработку данных». Без этого анкета не открывается.
2. Бот по шагам спрашивает ФИО, филиал, должность и роль (агент / андеррайтер / администратор);
   для агента — ID агента из реестра страховщика (Положение № 3845, п. 4).
3. Заявка уходит администратору. До подтверждения человек видит единственный экран «Ваша заявка на
   рассмотрении» — ни расчёта, ни запросов ему не доступно.
4. Администратор сверяет данные с реестром агентов и подтверждает либо отклоняет; решение пишется в журнал.
5. Пароль при таком входе не нужен: личность подтверждает Telegram. Вход по логину и паролю остаётся
   как запасной путь для уже заведённых учётных записей.

Номер телефона бот запрашивает отдельной кнопкой и только с отдельного согласия; отказ не мешает работе.

## Первый администратор — одноразовый код

Пока в системе нет ни одного активного администратора, подтверждать заявки некому. Первый администратор
создаётся так: на сервере задаётся переменная `ADMIN_BOOTSTRAP_CODE`, человек отправляет боту `/admin <код>`
и получает роль «админ». Код срабатывает один раз и только при условии, что активных администраторов ещё нет;
после использования он гасится. Событие записывается в журнал с датой и telegram_id.

Прежний порядок («первая заявка с ролью админ при пустой базе становится активной автоматически») отменён:
он позволял стать администратором любому, кто первым нашёл адрес системы.

## Кто что видит

| Роль | Доступ |
|---|---|
| Агент | новый расчёт, свои запросы, предложение клиенту |
| Андеррайтер | все запросы, решения по ним, портфельный аудит |
| Актуарий | калибровка, ёмкость и удержание, версии тарифов |
| Администратор | всё, включая заявки пользователей, справочники, генеральные соглашения, журнал и раздел «Запуск и обслуживание» |

Согласование запросов («Ждут меня», решения по генеральному соглашению) — у андеррайтера и администратора.
Подробная таблица прав и расхождения с матрицей `PERMISSIONS` в коде — в `docs/Регистрация и роли.md`, разделы 3 и 4.

## Как отключается уволенный агент

Администратор ставит статус «заблокирован» — вход закрывается сразу, действующие сессии обрываются.
Если агент исключён из реестра компании, вход невозможен даже с верным паролем.

## Что пишется в журнал

Заявка, подтверждение и отклонение, вход, неудачные попытки входа, блокировка, выход, создание первого
администратора по одноразовому коду.

В журнал **не пишутся** ФИО, телефон, адрес, паспортные данные и любые сведения о страхователе и застрахованном
имуществе — только telegram_id, user_id, логин, тип события и дата (ЗРУ-547 ст. 10 и 19, ЗРУ-730 ст. 62).
Полный перечень разрешённого и запрещённого — в `docs/Регистрация и роли.md`, раздел 7.

## Что нужно для кода в Telegram

Бот Telegram и его токен (переменная `TG_BOT_TOKEN` на сервере). Пользователь один раз пишет боту «/start» —
после этого коды приходят ему в чат. Без бота вход работает по паролю.

## Как хранятся пароли

Пароль в базе не хранится — только его хэш (PBKDF2-SHA256, 200 000 итераций, своя соль на каждого пользователя).
Восстановить пароль из базы нельзя; сменить — может администратор.
