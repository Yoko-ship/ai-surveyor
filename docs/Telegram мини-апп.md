# Мини-апп в Telegram: как завести и открыть

Инструкция для заказчика. Технических знаний не нужно: всё делается в чате Telegram и на одной странице нашей системы.
Времени — примерно 15 минут.

## Что такое мини-апп

Это наш экран расчёта, который открывается прямо внутри Telegram, без установки программы.
Агент нажимает кнопку в чате с ботом — открывается страница: выбрать продукт, ввести сумму, получить ставку,
сфотографировать объект, приложить техпаспорт.

Бот — это «дверь» в мини-апп. Сам расчёт делает наш сервер, бот только открывает окно.

---

## Шаг 1. Создать бота у @BotFather

1. Откройте Telegram и в поиске наберите `@BotFather`. Выберите чат с синей галочкой — это официальный бот Telegram.
2. Нажмите **Start** (или напишите `/start`).
3. Напишите в чат: `/newbot`
4. BotFather спросит имя бота — это то, что увидит агент в заголовке чата. Напишите, например:
   `INSON Сюрвейер`
5. BotFather спросит имя пользователя (username). Оно должно быть латиницей и заканчиваться на `bot`. Например:
   `inson_surveyor_bot`
   Если такое имя занято, BotFather скажет об этом — придумайте другое, например `inson_survey_bot`.
6. В ответ BotFather пришлёт сообщение со словами **Use this token to access the HTTP API** и длинную строку вида
   `8123456789:AAH4k...` — **это и есть токен**.

## Шаг 2. Сохранить токен

Токен — это пароль от бота. Кто его знает, тот управляет ботом.

- Не пересылайте токен в общие чаты и не выкладывайте в переписку с подрядчиками.
- Если токен всё-таки ушёл не туда — напишите BotFather `/revoke`, выберите бота, он выдаст новый токен, старый перестанет работать.

Скопируйте токен из чата длинным нажатием на сообщение → «Копировать».

## Шаг 3. Вписать токен в нашу систему

1. Откройте в браузере страницу **«Деплой и состояние системы»**: адрес сервера + `/admin/deploy`
   (на тестовом сервере это `http://127.0.0.1:8000/admin/deploy`).
2. Найдите блок **«Настройки»**, поле **«Токен бота Telegram»**. Вставьте туда токен.
   Поле показывает точки — это нормально, ключи на экране не показываются целиком.
3. В поле **«Адрес сервера»** впишите адрес, по которому наша система доступна из интернета, например
   `https://survey.inson.uz`. Он должен начинаться с `https://` — Telegram открывает мини-апп только по защищённому адресу.
4. Нажмите **«Сохранить настройки»**.

## Шаг 4. Указать Telegram адрес мини-аппа

Вернитесь в чат с @BotFather.

**Кнопка рядом с полем ввода (самый удобный способ):**

1. Напишите `/setmenubutton`
2. BotFather предложит выбрать бота — выберите своего.
3. Он спросит адрес — отправьте: `https://ваш-адрес/tg`
   (например `https://survey.inson.uz/tg`; `/tg` в конце обязательно — это страница мини-аппа).
4. Он спросит текст кнопки — отправьте: `Расчёт`

**Если нужна ещё и кнопка внутри бота:** `/mybots` → выберите бота → **Bot Settings** → **Menu Button** → **Configure menu button**.
Там те же два вопроса: адрес и надпись.

## Шаг 5. Открыть мини-апп на телефоне

1. В Telegram найдите своего бота по username (например `@inson_surveyor_bot`).
2. Нажмите **Start**.
3. Внизу слева, рядом с полем ввода сообщения, появится кнопка **«Расчёт»**. Нажмите её — откроется наш экран.
4. Первый раз система скажет, что ваш Telegram не привязан к учётной записи агента, и подаст заявку.
   Администратор подтвердит её на странице `/admin` — после этого можно сохранять запросы.
   До подтверждения расчёт считается, но не сохраняется.

Внизу экрана — четыре раздела: **Расчёт**, **Фото**, **Документы**, **Профиль**.
Кнопка **«Посчитать»** появляется внизу, её рисует сам Telegram.

## Порядок фотографий пока не сохраняется

В разделе **Фото** снимки можно перетаскивать пальцем и выстраивать в нужном порядке. Но этот порядок
живёт только на экране телефона: сервер его не запоминает. Закроете мини-апп или откроете запрос
с другого устройства — фотографии встанут в том порядке, в котором вы их загрузили.

Поэтому загружайте снимки сразу в нужной последовательности. Сохранение порядка на сервере сделаем
отдельной задачей.

## Предупреждение: персональные данные

**Пока сервер тестовый и находится за пределами Узбекистана, в мини-апп нельзя вводить данные реальных клиентов.**

Это правило проекта № 8: персональные данные граждан Узбекистана хранятся только на серверах в Узбекистане.
Пока хостинг не перенесён в страну, вводите только учебные примеры: условный объект, условные суммы,
вымышленное название страхователя. Настоящие фамилии, паспорта, ИНН, адреса объектов клиентов, фотографии
с адресными табличками — нельзя.

На экране мини-аппа об этом висит оранжевая полоса. Она исчезнет, когда администратор переключит режим
персональных данных на «боевой» — а переключить его можно только после переноса сервера в Узбекистан.
Страница `/admin/deploy` спрашивает подтверждение перед таким переключением и объясняет последствия.

## Бот: что он умеет сам

Мини-апп — это экран. Бот — это чат, в котором можно всё сделать без экрана:
зарегистрироваться, узнать свою роль и согласовать запрос одной кнопкой.

**Команды бота**

| Команда | Что делает |
|---|---|
| `/start` | Регистрация нового человека или вход, если он уже подтверждён |
| `/me` | Кто я: роль, филиал, состояние учётной записи |
| `/inbox` | Запросы, которые ждут именно моего решения, с кнопками «Одобрить», «Отклонить», «Вопрос» |
| `/help` | Короткая подсказка |
| `/admin КОД` | Разовый код первого администратора (см. ниже) |

**Как проходит регистрация**

1. Человек пишет боту `/start`.
2. Бот показывает текст согласия на обработку персональных данных и кнопку «Согласен».
   Без согласия регистрация не продолжается. Факт согласия, его версия и дата сохраняются.
3. Дальше бот спрашивает по одному: ФИО → филиал → должность → роль (кнопки «Агент», «Андеррайтер»,
   «Администратор»). Для агента — ещё ID агента из реестра компании; если такого ID в реестре нет,
   бот честно об этом говорит и просит ввести заново.
4. Заявка уходит **всем администраторам** с кнопками «Подтвердить как агент»,
   «Подтвердить как андеррайтер», «Отклонить». Роль при подтверждении можно поменять — это попадает в журнал.
5. Пока заявку не подтвердили, и бот, и мини-апп показывают одно: «ожидает подтверждения администратора».

Начатую и брошенную регистрацию можно начать заново командой `/start` — черновик хранится в базе,
перезапуск сервера его не теряет.

**Согласование в чате**

Когда по запросу назначены согласующие, каждому из них (у кого привязан Telegram) приходит карточка:
продукт, объект, страховая сумма, ставка, премия, кто подал, партнёр по генеральному соглашению.
Под карточкой три кнопки: «Одобрить», «Отклонить», «Вопрос» (бот попросит написать вопрос сообщением).

Решение записывается от имени того, **чей Telegram нажал кнопку**, — подставить чужую фамилию нельзя.
Если человек не назначен согласующим по этому запросу, бот отвечает отказом и ничего не записывает.
После нажатия карточка обновляется: кнопки исчезают, видно решение. Когда запрос окончательно
согласован или отклонён, уведомление уходит и тому, кто подал запрос, и всем согласующим.

**Что попадает в журнал бота.** Только идентификатор Telegram, номер нашего пользователя, тип события
(регистрация, команда, нажатие кнопки, уведомление, отказ) и признак «дошло / не дошло».
Ни текстов сообщений, ни ФИО, ни телефонов, ни сведений о страхователе в журнале нет — правило проекта № 8.

## Вход через Telegram из обычного браузера (с 21.09.2026)

Мини-апп внутри Telegram входит сам. Если ту же страницу открыть в обычном браузере (на компьютере),
Telegram про нас ничего не знает — поэтому вход идёт «обратным кодом», без виджетов Telegram
и без каких-либо настроек у @BotFather:

1. На странице входа человек нажимает **«Войти через Telegram»**. Сервер показывает одноразовый код
   вида `INS-7K3M` — он живёт 10 минут.
2. Человек нажимает **«Открыть бота»** (откроется чат с ботом, кнопка «Запустить») либо просто пишет
   этот код боту сообщением.
3. Бот принимает код, узнаёт, от кого он пришёл, и отвечает «Готово, вернитесь в браузер».
   Страница входит сама — обновлять её не нужно.
4. Если человек в системе впервые, дальше открывается обычная анкета (номер телефона, ФИО,
   департамент, должность, согласия). Кода подтверждения телефона здесь не спрашиваем:
   Telegram уже подтверждён тем, что сообщение боту пришло именно от этого человека.

Почему это безопасно: код нигде не хранится в открытом виде, срабатывает один раз, гаснет через
10 минут; кто вошёл — определяется по отправителю сообщения в Telegram, а не по тексту.
Больше пяти кодов подряд одна страница получить не может.

Настройка одна и необязательная — `TG_BOT_USERNAME` (имя бота для ссылки «Открыть бота»).
Если её не задать, имя берётся у самого Telegram (getMe), а если и это недоступно —
показывается `@inson_surveyor_bot`.

## Настройки бота

Задаются на странице `/admin/deploy` или в файле `.env` рядом с сервером.

| Настройка | Зачем | Обязательна |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен от @BotFather. Без него бот молчит, а система работает как обычно в браузере | да, для бота |
| `SERVER_URL` | Адрес системы в интернете, начиная с `https://` | да, для бота |
| `TG_WEBHOOK_SECRET` | Секретная часть адреса, на который Telegram присылает сообщения. Если пусто — создастся сама при настройке | нет |
| `ADMIN_BOOTSTRAP_CODE` | Разовый код первого администратора | только при первом запуске |
| `TG_POLLING` | `1` — запасной режим для машины без адреса в интернете (система сама спрашивает Telegram о новых сообщениях). На боевом сервере не нужен | нет |
| `CONSENT_VERSION` | Версия текста согласия на обработку данных | нет |

**Первый администратор.** Пока в системе нет ни одного администратора, подтверждать заявки некому.
Поэтому: впишите в `ADMIN_BOOTSTRAP_CODE` любое длинное слово, известное только вам, напишите боту
`/admin ваше-слово` — и вы станете администратором. Код после этого гасится: второй раз он не сработает,
и нигде — ни на экранах, ни в журнале — он не показывается.

## Подключение бота: один скрипт

После того как токен и адрес сервера сохранены, выполните на сервере:

    sandbox\.venv\Scripts\python.exe tools	g_setup.py

Скрипт сам: проверит токен, скажет имя бота, поставит адрес для приёма сообщений (вебхук),
повесит кнопку «Открыть сюрвейер» рядом с полем ввода и запишет список команд.
Проверить состояние потом: `tools	g_setup.py --show`.

Если токена нет — скрипт ничего не делает и печатает, что именно нужно сделать. Токен и секрет он не печатает.

**Локальная машина без адреса в интернете.** Вебхук поставить нельзя (Telegram должен достучаться до сервера).
Для проверки на месте поставьте `TG_POLLING=1` и перезапустите сервер — система сама будет спрашивать
Telegram о новых сообщениях. На боевом сервере этот режим выключают: вебхук быстрее и не нагружает сеть.

## Если что-то не работает

| Что видно | Что это значит | Что делать |
|---|---|---|
| Кнопки «Расчёт» нет в чате | Адрес мини-аппа не задан | Повторить шаг 4 (`/setmenubutton`) |
| Открылось пустое белое окно | Наш сервер недоступен из интернета или адрес без `https` | Проверить адрес в поле «Адрес сервера» и работу сервера |
| «Ваш Telegram не привязан» | Заявка подана, но не подтверждена | Администратор подтверждает её на странице `/admin`, сверив ID агента |
| «Сервер не подтвердил вход» | Сервер не ответил | Проверить, запущен ли сервер (`run.bat`), и лог `sandbox/server.log` |
| «Справочники не загрузились» | База не поднялась | Открыть `/admin/deploy`, нажать «Проверить схему» |
| Бот не отвечает на `/start` | Не задан токен или не поставлен вебхук | Проверить `/admin/deploy` и запустить `tools/tg_setup.py` |
| Бот отвечает «Вы не назначены согласующим» | Кнопку нажал не тот, кого назначили | Проверить состав согласующих на странице `/approvals` |
| Код администратора не срабатывает | Код уже использован один раз | Задать новый `ADMIN_BOOTSTRAP_CODE` или попросить действующего администратора подтвердить заявку |
