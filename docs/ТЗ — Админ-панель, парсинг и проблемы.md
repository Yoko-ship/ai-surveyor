# ИИ-сюрвейер: ТЗ для админ-панели, каналы парсинга и открытые проблемы

Версия от 01.10.2026. Документ для программиста и руководства страховой организации.

## Часть 1. ТЗ для админ-панели

### 1.1. Исходное задание заказчика

Заказчик дал задание от руки на узбекском языке. Ниже оно дословно и в переводе.

| № | Как написано | Перевод |
|---|---|---|
| 1 | Сайт бўлиши керак | Должен быть сайт |
| 2 | Ходим қўшиш: Ф.И.О.; лавозим; департамент / бўлим (қаерда ишлаши) / филиал; логин / парол; тел. номер | Добавление сотрудника: Ф.И.О.; должность; департамент / отдел (где работает) / филиал; логин и пароль; номер телефона |
| 3 | Суғурта маҳсулоти қўшиш: продукт коди / номи / тариф (импорт қилиш керак) | Добавление страхового продукта: код продукта / название / тариф (нужен импорт) |
| 4 | Суғурта маҳсулоти бўйича суғурта ҳодисаси маълумотларини юклаш жойи: 1-йил / продукт коди / номи / суғурта ҳодисаси сони / суммаси; 2-йил; 3-йил | Место для загрузки данных о страховых случаях по продукту: 1-й год / код продукта / название / число страховых случаев / сумма; 2-й год; 3-й год |

### 1.2. Что уже есть и чего нет

| Требование | Есть сейчас | Чего не хватает |
|---|---|---|
| 1. Сайт | Админка работает как сайт по адресу `/admin/hub` | Отдельный вход по логину и паролю как основной способ; сейчас основной вход — через Telegram |
| 2. Сотрудники | Список пользователей, выдача прав администратора, имя, департамент, должность | Создание сотрудника администратором с логином и паролем, филиал, телефон, отключение, сброс пароля, импорт списком |
| 3. Продукты | Справочник из 176 продуктов с кодами, названиями, классами и минимальными ставками; просмотр | Добавление и правка продукта в админке, импорт из Excel, версии тарифа с датой |
| 4. Страховые случаи | Модуль калибровки и загрузка портфеля в Excel | Простая форма «год — продукт — число случаев — сумма» и использование этих данных в акте |

### 1.3. Шаг 1. Сайт

1. Админка открывается по отдельному адресу в браузере на компьютере и телефоне.
2. Вход по логину и паролю. Вход через Telegram остаётся вторым способом.
3. После пяти неверных попыток вход блокируется на 15 минут.
4. Сессия заканчивается через 8 часов бездействия.
5. Меню слева: Сотрудники, Продукты и тарифы, Страховые случаи, Шаблоны классов, Финансы, Рынок, Настройки, Журнал.
6. Языки интерфейса: узбекский, русский, английский.

Готово, когда: администратор входит по логину и паролю и видит все разделы; сотрудник без прав получает отказ.

### 1.4. Шаг 2. Сотрудники

Форма «Добавить сотрудника»:

| Поле | Обязательное | Проверка |
|---|---|---|
| Ф.И.О. | да | не пустое, до 150 знаков |
| Должность | да | выбор из списка или свой текст |
| Департамент или отдел | да | выбор из справочника подразделений |
| Филиал | да | выбор из справочника филиалов |
| Логин | да | уникальный, латиница и цифры, от 4 знаков |
| Пароль | да | от 8 знаков, буквы и цифры; хранится только в зашифрованном виде |
| Номер телефона | да | формат +998 и 9 цифр, уникальный |
| Роль | да | сотрудник, андеррайтер, администратор |

Что должно работать:

1. Добавление, правка, отключение сотрудника. Удаления нет: отключённый сотрудник не может войти, его акты сохраняются.
2. Сброс пароля администратором. При первом входе сотрудник обязан сменить пароль.
3. Справочники «Департаменты» и «Филиалы» с добавлением и правкой.
4. Импорт сотрудников из Excel по шаблону, с отчётом об ошибках по строкам.
5. Поиск и отбор по филиалу, департаменту, роли.
6. Каждое изменение записывается в журнал: кто, когда, что изменил.

Готово, когда: администратор заводит сотрудника, тот входит под своим логином, меняет пароль и видит только то, что положено его роли.

### 1.5. Шаг 3. Страховые продукты

Форма «Добавить продукт»:

| Поле | Обязательное | Проверка |
|---|---|---|
| Код продукта | да | 4 цифры, уникальный |
| Название | да | на трёх языках; русское обязательно |
| Класс страхования | да | выбор из справочника; можно несколько классов |
| Тариф | да | процент годовых, либо «по программе», либо «по нормативному акту» |
| Минимальная ставка | нет | не больше тарифа |
| Дата начала действия | да | тариф действует с этой даты |

Что должно работать:

1. Добавление и правка продукта. Старый тариф не стирается: новая строка с датой начала действия, старые акты пересчитываются по тарифу своей даты.
2. Импорт из Excel по шаблону: код, название, класс, тариф, минимальная ставка, дата. Перед записью — предпросмотр: что добавится, что изменится, какие строки с ошибкой.
3. Выгрузка всего справочника в Excel.
4. Отключение продукта: в мини-приложении он не предлагается, в старых актах остаётся.
5. Журнал изменений тарифов.

Готово, когда: администратор загружает файл тарифной политики, видит предпросмотр, подтверждает, и новый продукт появляется в мини-приложении с правильной ставкой.

### 1.6. Шаг 4. Страховые случаи по продуктам

Форма и импорт «Данные о страховых случаях»:

| Поле | Обязательное | Проверка |
|---|---|---|
| Год | да | три последних года; можно больше |
| Код продукта | да | есть в справочнике |
| Название продукта | подставляется само | по коду |
| Число страховых случаев | да | целое, не меньше нуля |
| Сумма выплат | да | в сумах, не меньше нуля |

Предложение сверх задания заказчика — добавить два необязательных столбца: число договоров и сумма премий за год. Без них нельзя посчитать убыточность и частоту случаев, а именно они нужны для ставки.

Что должно работать:

1. Ввод вручную и импорт из Excel по шаблону, с предпросмотром и отчётом об ошибках.
2. Повторная загрузка того же года и продукта заменяет прежние цифры, прежние сохраняются в истории.
3. Сводная таблица: продукт, три года, число случаев, сумма, а при наличии премий — убыточность и частота.
4. Использование в акте:
   - в разделе 4 строка «Убытки по продукту за 3 года: случаев …, выплат …, убыточность …»;
   - в вилке ставки поправка по убыточности продукта вместо рыночной, когда данных достаточно;
   - пометка «по данным страховщика за 2023–2025 годы».
5. Правило применения поправки утверждает актуарий страховщика. До утверждения цифры показываются справочно.

Готово, когда: администратор загружает файл за три года, видит сводку, а в акте по этому продукту появляется строка с убытками.

### 1.7. Порядок работы программиста

| День | Работа |
|---|---|
| 1 | Вход по логину и паролю, блокировка, сессии, меню |
| 2 | Сотрудники: форма, справочники филиалов и департаментов, роли, сброс пароля |
| 3 | Импорт сотрудников, журнал, проверки доступа |
| 4 | Продукты: форма, версии тарифа, импорт и выгрузка Excel |
| 5 | Страховые случаи: форма, импорт, сводка |
| 6 | Вывод убытков в акт и в вилку ставки, проверки, выкладка |

### 2.4. Правила для каждого канала

1. До подключения — проверить правила сайта и наличие официального способа получения данных.
2. Программа представляется своим именем, запрашивает не чаще одного раза в секунду, при отказе не повторяет запрос.
3. Данные хранятся с датой получения и ссылкой на источник. В акте под каждой внешней цифрой — источник.
4. Если сайт недоступен, акт формируется по последним сохранённым данным с пометкой даты.
5. Имена клиентов, адреса и другие персональные данные в запросы к внешним сайтам не попадают.
6. При изменении устройства сайта канал отключается сам и сообщает администратору, а не отдаёт неверные цифры.

## Часть 3. Открытые проблемы

### 3.1. Останавливают запуск

| № | Проблема | Чем грозит | Что делать | Кто |
|---|---|---|---|---|
| 1 | Сервер находится за рубежом | Персональные данные клиентов и сотрудников вести нельзя | Арендовать сервер в Узбекистане, перенести систему | Страховщик, затем программист |

### 3.5. Что нужно решить страховщику

1. Сервер в Узбекистане: у кого и когда.
2. Кто утверждает экспертные числа: актуарий или андеррайтер.
3. Включать ли поправки региона и рынка в основную ставку или показывать справочно.
4. Нужен ли прямой договор с кредитным бюро и с площадками объявлений.
5. Какие роли сотрудников нужны и что каждой разрешено.
