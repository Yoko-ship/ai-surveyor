# ИИ-сюрвейер INSON — как запустить и подключить

## Что это

Сервер, который принимает данные о страхуемом объекте, считает ставку, проверяет договор по законодательству
и тарифной политике, подсказывает, как снизить премию, и хранит все запросы с расчётами для аналитики.
Внутри: база справочников (классы, риски, продукты, минимальные тарифы, коэффициенты, чек-листы, правила),
движок расчёта, API, экран агента и админка.

## Запуск на своём компьютере (для просмотра)

1. Установлен Python 3.10 или новее.
2. Двойной щелчок по `run.bat` — или в консоли:
   ```
   python -m venv sandbox\.venv
   sandbox\.venv\Scripts\pip install -r requirements.txt
   python tools\db_build.py
   sandbox\.venv\Scripts\python -m uvicorn app.main:app --port 8000
   ```
3. Открыть http://localhost:8000 — там ссылки на экран агента, админку и описание API.

## Запуск на сервере компании

`Dockerfile` в корне: `docker build -t surveyor . && docker run -p 8000:8000 -v surveyor-data:/srv/data surveyor`.
База — SQLite в папке `data/`. Для промышленной эксплуатации переносится на PostgreSQL: схема в `db/schema.sql`
написана без диалектных особенностей, слой доступа — один файл `app/db.py`.

**Персональные данные граждан Узбекистана должны храниться на серверах внутри страны** (Положение 3571, п. 21).

## Первое, что нужно сделать после запуска

В админке (`/admin`):
1. Ввести **собственные средства и страховые резервы** на последнюю отчётную дату — без них не проверяется лимит 20% на один риск.
2. Проверить минимальные ставки: загружены из тарифной политики 54-П от 23.09.2025. Новую редакцию заводить как новую версию тарифов с датой вступления.
3. Когда появится статистика компании — заменить экспертные коэффициенты (`calibrated = 0`) на рассчитанные.

## Подключение к учётной системе

Филиал или учётная система отправляет запрос — `POST /requests` с JSON:

```json
{
  "external_no": "0275/0807/26/0031",
  "branch": "Навоийский филиал",
  "product_code": "0807",
  "policyholder": "ООО Пример",
  "beneficiary": "АКБ Пример-банк",
  "object_type": "Склад",
  "address": "г. Ташкент, ул. Пример, 1",
  "value_amount": 4200000000,
  "sum_insured": 4200000000,
  "term_days": 365,
  "factors": {"construction": "mixed", "activity": "warehouse", "protection": "alarm",
              "seismic": "z8", "wear": "mid", "loss_history": "clean", "franchise": "f0"},
  "docs_received": ["Заявление-анкета на страхование", "Документ о праве на объект"],
  "premium_paid": false
}
```

Ответ — расчёт целиком: ставки (техническая, минимальная, применённая), премия, построчное объяснение,
список проверок со ссылками на нормы, вердикт (`ок` / `на утверждение` / `отклонено`) и рекомендации с экономией в сумах.

Дальше:
- `GET /requests/{id}` — карточка запроса; `POST /requests/{id}/documents` — загрузка файлов;
- `POST /requests/{id}/decision` — решение андеррайтера.

Расчёт «на лету» без сохранения — `POST /calculate` с теми же полями.
Для кредитных продуктов добавляется блок `"credit": {"loan_amount", "collateral_value", "policyholder_is_bank", "payer_is_bank"}`.
Полное описание всех полей — на `/docs` у запущенного сервера.

## Рыночная статистика: обновляется сама

- Сервер раз в сутки сам проверяет сайт НАПП, скачивает новые квартальные отчёты, разбирает их и дописывает
  временной ряд в таблицу `market_stats` (агент-статистик, поток внутри сервера; первая проверка — через минуту после старта).
- Страница **/stats** — динамика по любой строке отчёта: премии за квартал, убыточность, средняя годовая ставка,
  обязательства; таблица срезов; кнопка «Проверить НАПП сейчас».
- API: `GET /market/rows`, `GET /market/series?row=cls8_9`, `POST /market/refresh`, `GET /market/status`.
- Сейчас загружено 9 срезов: с марта 2024 по июль 2026. Отчёт за I квартал 2026 на сайте НАПП повреждён.
- Ручной запуск: `python tools/market_stats.py --refresh`.

Страница **/graph** — паутина знаний в стиле Obsidian: продукты → классы → учётные группы → правила РНП.

## Предупредительные мероприятия для страхователя

Движок подбирает предписания по факторам риска (справочник `preventive_measures`, 10 записей для классов 8 и 9):
установить сигнализацию, охрану, спринклеры, огнезащитная обработка, проверка проводки, обследование сейсмостойкости,
защита от кражи, инвентаризация. У каждого — зачем, эффект на премию и признак **условие договора со сроком**,
если страховая сумма выше порога. Это не РПМ: резерв компания не ведёт, а предписания выдаёт.
В ответе `POST /calculate` — поле `preventive_measures`; на экране агента — отдельный блок в панели расчёта.

## Ёмкость, резервы, собственное удержание

Страница **/capacity-page** и `GET /capacity`: лимит 20% на один риск и 200% на пять крупнейших (Положение 1806),
маржа платёжеспособности, резервы по учётным группам, выделенные активы (норма 100–105% и ≥ 70% ликвидных, Положение 1882),
таблица собственного удержания по классам (таблица линий: равная чистая премия с удержания, потолок — лимит 20%).
Чего нет — страница запрашивает списком: приложения к Положениям 1806 и 1882, которые компания сдаёт в НАПП.
Ввод: `PUT /admin/solvency`, `POST /admin/reserves`, `POST /admin/assets`. Знание — `docs/Резервы, ёмкость и собственное удержание.md`.

## Офис агентов и поиск законов

**/office** — семь агентов в виде роботов за столами; статус и последнее действие берутся из журнала.
Агент-юрист сам находит недостающие акты на lex.uz: `python tools/lex_fetch.py <url|номер> --name "<название>"`
— текст попадает в `library/01_Законодательство`, каталог пересобирается, действие пишется в журнал.
Уже загружены с lex.uz: Закон «О страховой деятельности» ЗРУ-730 (редакция с ЗРУ-1154) и глава 52 ГК (ст. 914–961).

## Портфельный аудит, предложение клиенту, калибровка

- **/portfolio** — загрузка Excel-выгрузки договоров из учётной системы: колонки сопоставляются автоматически
  (русский/узбекский/латиница), код продукта берётся из вида страхования или номера договора, каждый договор проходит
  через движок. Сводка: ниже минимума, ниже технической, сумма выше стоимости, без франшизы, недополученная премия,
  топ филиалов и продуктов. API: `POST /portfolio/import`, `GET /portfolio/batches/{id}`, `.../summary`.
- **`GET /requests/{id}/proposal.pdf`** — предложение клиенту: объект, цена, из чего сложилась ставка, покрытые и
  исключённые риски, как снизить стоимость, предупредительные мероприятия, обязательная информация по ст. 63.
  Ссылка есть на экране расчёта после сохранения и в таблице запросов админки.
- **/calibration** — самообучение ставок: регистрация убытков (`POST /claims`), прогон по периоду
  (`POST /calibration/run`): burning cost по группам, теория доверия Z = √(n/1000), рисковая надбавка по формуле
  с коэффициентом гарантии, предложения по базовым ставкам и множителям факторов. Применяются только через
  `approve` — создаётся новая версия тарифа, значения помечаются `calibrated = 1`. Порог: 30 договоров и 5 убытков в группе.
- В каждом расчёте — **сравнение с рынком**: средняя годовая ставка и убыточность по классу из последнего среза НАПП.
- **Главная /** — плитки с живыми цифрами; единое тёмное боковое меню на всех страницах.

## Темы, бренд, офис, автообновление и история

- **Светлая и тёмная тема** — переключатель внизу справа на любой странице; выбор запоминается в браузере.
  Логотип InsuranceON (синий INS, зелёный ON) в меню. Ссылка с `?theme=light` открывает страницу в светлой теме.
- **/office** — сцена офиса: семь роботов за столами, экраны горят у тех, кто работает; пузыри с текущим действием
  из журнала; журнал офиса внизу.
- **Автообновление данных.** Рынок — отчёты НАПП раз в сутки. Договоры — папка `data/inbox/portfolio`: положите
  туда xlsx, сервер импортирует её в течение 10 минут (`POST /portfolio/auto-import` — вручную).
- **История и связь загрузок.** `GET /portfolio/history/{номер договора}` — все загрузки и запросы по договору с тем,
  что менялось; `GET /portfolio/batches/{id}/diff` — сравнение с предыдущей загрузкой: новые, исчезнувшие, изменившиеся,
  ставшие «отклонено». На странице портфеля это показывается строкой над сводкой.

## Что проверяет система

| Проверка | Норма | Действие |
|---|---|---|
| Страховая сумма выше стоимости | ГК ст. 938 | стоп |
| Страховая сумма ниже стоимости | ГК ст. 936 | предупреждение о пропорциональной выплате |
| Ставка ниже минимума по продукту (по классу, не по средней) | тарифная политика / регулятор | стоп |
| Ставка ниже технической | — | предупреждение, попадает в аналитику |
| Лимит 20% на один риск | Положение 1806, п. 15 | стоп |
| Кредит: только необеспеченная часть, не более 50% кредита; страхователь и плательщик — банк | требование регулятора | стоп |
| Премия не поступила | Закон о страховой деятельности, ст. 33¹ | предупреждение |
| Клиенту не раскрыта информация | ст. 63 | предупреждение |
| Не хватает обязательных документов | чек-листы | предупреждение |
| Ручная ставка без причины | внутреннее правило | стоп |

## Контрольные примеры

`sandbox\.venv\Scripts\python tests\test_engine.py` — пять сценариев: склад, превышение и недострахование,
кредит с залогом, договор КАСКО с проверкой по классам, ручная ставка без причины.

## Что пока не сделано и почему

- **Извлечение данных из загруженных документов** — файлы сохраняются; распознавание подключается после выбора площадки (сервер компании или облако) — это вопрос, где будут обрабатываться персональные данные.
- **Калибровка ставок** — ждём выгрузки договоров и убытков. До этого все базовые ставки и коэффициенты экспертные и помечены.
- **Определение по фото** работает на экране агента через Claude на аккаунте пользователя; в серверной версии нужен ключ API компании.

```
tools/      сборка базы и библиотеки, разбор Excel, загрузка отчётов НАПП

```
