# ИИ-сюрвейер INSON — описание проекта

Проверено по исходникам и локальному запуску 05.10.2026. Подготовлены Python 3.12.10, `sandbox/.venv` и рабочая база; сервер прошёл HTTP-проверку. Условия запуска и ограничения находятся в [docs/RUN_READINESS.md](docs/RUN_READINESS.md); история работы — в [WORK_LOG.md](WORK_LOG.md).

## Зачем нужен проект

Это помощник сотрудника страховой компании INSON в Узбекистане. Он собирает сведения о страхуемом объекте, читает документы и фотографии, помогает оценить риск, рассчитывает ставку и премию, объясняет результат и формирует сюрвейерский акт. Окончательное решение остаётся за человеком.

Основной пользовательский путь в мини-приложении: **Фото → Проверить → Акт**. Дополнительно доступны калькулятор, ОСГОР, специалист по страховым вопросам и административные разделы. Интерфейс рассчитан на русский, узбекский и английский языки.

## Как устроено приложение

Это модульный монолит FastAPI. Сборка — `app/application.py`, совместимая точка запуска — `app/main.py`; подробности в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Uvicorn обслуживает API и HTML/CSS/JavaScript из того же проекта. Отдельная сборка React, Node.js или npm для штатного запуска не нужна; материалы в `docs/design/` — отдельные прототипы.

Данные хранятся в SQLite. По умолчанию база — `data/surveyor.db`; переменная процесса `STORAGE_DIR` переносит рабочее хранилище в другую папку. В нём также живут загрузки, фотографии, отчёты и другие созданные данные. `app/db.py` управляет соединениями и копированием, `app/infrastructure/migrations.py` — версиями схемы; `app/refsync.py` обновляет справочники из поставки.

При старте приложение обновляет схему и запускает фоновые задачи: рыночные данные, входящие отчёты, статистика, законодательство, очистка временных материалов и другие задания. HTTP обслуживает **один процесс**; расписание работает в нём (`embedded`) либо в отдельном `python -m app.worker` (`external`) с той же базой. Блокировка ОС не допускает двух планировщиков. Для диагностики фоновые задачи выключаются через `SURVEYOR_NO_BACKGROUND=1`.

Языковая модель подключается через `app/llm.py` к совместимому API. Вычисления по тарифам используют собственный движок. Без ключа возможны локальные расчёты и шаблонные ответы, но нельзя считать проверенными распознавание фото и полноценные ответы модели. Telegram и вход через Google тоже требуют отдельных настроек.

Для закрытого тестирования двух аккаунтов включён приватный шлюз
`app/codex_gateway.py` → Railway HTTPS → `tools/codex_gateway.py` в отдельном
сервисе codex-gateway → Codex CLI 0.160.0 с отдельным входом ChatGPT на volume.
Telegram ID проверяются по подписи и allowlist; серверный ключ шлюза отделён
от авторизации ChatGPT. Обе части работают на Railway, Mac не участвует.
Исполнитель `app/codex_runtime.py` обрабатывает только переданные данные, без
доступа к инструментам и рабочему репозиторию. Один запрос за раз, sleep выключен,
restart ALWAYS; действуют квоты подписки и возможный повторный вход.
Отдельный прямой SIWC/Responses-адаптер `app/chatgpt_plan.py` остаётся выключенным:
его первоначальный OAuth-вход не реализован. Настройки и границы обоих способов
описаны в README, фактическая публикация — в WORK_LOG. Тарифные расчёты не менялись.

## Основные адреса после запуска

- `/tg` — мини-приложение, также открывается браузером.
- `/ui` — экран расчёта.
- `/admin/hub` — административный центр.
- `/stats`, `/portfolio`, `/capacity-page`, `/calibration` — специализированные разделы.
- `/login` — вход и первоначальная настройка администратора.
- `/health` — состояние сервера; `/docs` — описание API в локальном режиме разработчика.

Доступ определяется `app/guard.py` и проверками ролей конкретных маршрутов. Локальный режим не означает, что все действия администратора разрешены без пользователя.

## Данные и границы готовности

Первичная сборка из поставляемых файлов 05.10.2026 дала 176 продуктов, 20 записей классов, 20 шаблонов анализа, 934 вида деятельности ОСГОР и 22 отслеживаемых акта. Рыночная загрузка дала 771 строку на девять дат срезов. Эти числа описывают проверенную поставку и могут измениться при обновлении справочников.

PostgreSQL пока не реализован: приложение напрямую использует SQLite, а непустой `DATABASE_URL` теперь вызывает ошибку конфигурации. При обновлении схемы сохраняется резервный снимок, версии учитываются в `schema_migrations`.

Интеграция с ЕАИС исключена из текущего объёма по прежнему решению заказчика. В старых материалах и полях могут оставаться упоминания ЕАИС. Экспертные коэффициенты требуют калибровки; тарифы, нормативы, собственные средства и резервы — подтверждения страховщика. Не следует принимать старые списки «готово/осталось» в ТЗ за текущее состояние без проверки.

По правилам проекта рабочие персональные данные должны размещаться в Узбекистане. Наличие конфигураций облачного размещения не подтверждает подходящее местоположение сервера. Текущая проверка охватывает репозиторий и локальное окружение; состояние опубликованного сервиса не проверялось.
